## 1. What this session did

Turned the ad-hoc checkpoint sequence that had been improvised across the night into a real skill. The sequence was
not designed up front; it accumulated one step at a time as the owner asked for durable peer artifacts, then durable
synthesis checkpoints, then compaction survival, then a handoff document, then transcript locations. `/handoff` is

The thing that would surprise someone who was not here: **the ceremony was built and then not run.** The owner asked
"did /handoff get run here?" and the answer was no. This document exists because of that question.

## 4. Findings

### H-1. The tooling that preserves work is itself unpreserved (HIGHEST)

`~/.claude` is **not a git repository** and has no `.git`. Verified directly:

```
$ git -C ~/.claude rev-parse --show-toplevel
fatal: not a git repository (or any of the parent directories): .git
```

Every skill, hook, and command in that tree exists on **one machine, with no version history and no push target**.
That includes the entire `/handoff` implementation, `mem-capture.sh`, the PreToolUse firewall guard, and the whole
skills library. A disk failure or an errant `rm` loses all of it silently.

`verify.sh` already surfaces this class of problem, emitting `WARN not a git repository, handoff is not backed up by
push` for any handoff written outside version control. That is how the gap was noticed.

**Not fixed, and deliberately not fixed unilaterally**, because `git init` on a directory holding credentials-adjacent
config is a decision with a blast radius the owner should own. See next actions.

### H-2. `main` in this repo has no upstream tracking branch

Surfaced by the snapshot script's first run.

```
$ git rev-parse --abbrev-ref '@{upstream}'
fatal: no upstream configured for branch 'main'
```

Pushes have all been explicit `git push origin main`. `origin/main` exists and matches HEAD, so **the work is safe**,
but any tool asking git "am I ahead of my upstream?" gets an error rather than an answer. The snapshot now falls back
to comparing against `origin/<branch>` and reports whether work is **safe** rather than whether it is **configured**.

Optional fix: `git branch --set-upstream-to=origin/main main`. Not applied; it changes push behavior and is the
owner's call.

### H-3. The manual invocation path was silent (fixed)

`handoff-snapshot.sh` only printed its output line on `PreCompact`. Invoked manually, as step 1 of the ceremony
instructs, it wrote the file and printed nothing, so the caller could not distinguish success from failure. Fixed with
a `case` on the event: `PreCompact` gets the full injected reminder, `SessionEnd` stays silent because nobody is
listening, anything else confirms the write path. Found by running the ceremony, not by reading the code.

## 5. Incidents and the rules they produced

**Built the thing, then did not use it.** The skill was finished, tested, wired, and reported as done, and the session
moved on without ever invoking it. The work of the preceding hour was therefore uncaptured until the owner asked.

> **RULE: a ceremony that is not run on the session that created it has not been tested.** Running it immediately
> found three defects (H-1, H-2, H-3), two of which are in the tooling itself. Shipping a process and demonstrating a
> process are different acts, and only the second produces evidence.

**A bash 3.2 assumption that was wrong in a useful direction.** `verify.sh` failed at runtime while passing
`bash -n`, and the first diagnosis was macOS's ancient bash mis-parsing a heredoc inside command substitution. The
shell is actually **bash 5.3**, so that theory was wrong; the real cause was quote nesting. The fix (moving the Python
into `check-paths.py`) was correct anyway, but the reasoning was not. Recorded because a fix that works for the wrong
reason is a trap for whoever touches it next.

## 6. Operating constraints

- **A hook can inject text. It cannot force skill invocation.** This is the owner's own note in `CLAUDE.md` and it is
  the single constraint that shapes the whole design. Everything requiring judgment must be assumed to not happen.
- **`SessionEnd` output goes nowhere.** There is no model left to read it, so the snapshot stays silent there and
  writes only to disk.
- **Hooks must fail open.** `handoff-snapshot.sh` was tested against empty stdin, garbage stdin, a non-git cwd, and a
  nonexistent cwd. All four exit 0.
- **Session directories are keyed by cwd**, so one session scatters artifacts across multiple `-Users-...` project
  slugs when the working directory changes.

## 7. Next actions, in priority order

**1. Decide what to do about `~/.claude` being unversioned (H-1).** This gates everything else, because until it is
resolved, every improvement to the skills library is one disk failure from gone. Options, cheapest first: a private
git repo with a `.gitignore` for anything credential-bearing; or a scheduled copy to the 2.110 storage box; or accept
the risk explicitly and write that down so it stops being an accident. **Requires an owner decision, not a default.**

**2. Run `/handoff` on a messier project.** Triumvirate is unusually well-behaved: clean tree, real remote, tidy docs
directory. The ceremony's assumptions have only been tested against the friendly case. A repo with no remote, or a
non-repo working directory, will exercise the fallback paths that are currently only reasoned about.

**3. Consider `git branch --set-upstream-to=origin/main main` (H-2).** Removes a class of confusing tool output. Not
urgent because the fallback handles it.

**4. Everything in `pantheon/HANDOFF-2026-08-26.md` section 7 still stands**, and its item 1 (build a real spend stop
before the first GPU VM) remains the highest-priority Pantheon action.

## 8. What was NOT verified

- **The `PreCompact` hook has never fired for real.** It was tested by piping hand-constructed JSON into the script.
  The actual hook payload shape on a real compaction is assumed, not observed. If the field names differ, the script
  falls back to cwd and glob resolution and still writes a file, but the transcript path could be wrong.
- **`SessionEnd` likewise has never fired for real** in this session.
- **The skill has not been invoked from a fresh session.** It was invoked once, here, in the session that wrote it,
  where its contents were already in context.
