## 5. The reranker incident, and the rule it produced

I stopped the `infinity` container to free VRAM after concluding it had no consumers. **It had one.** Graphiti
(`docker-graphiti-mcp-1`) on **homebox (192.168.2.110)** reaches it at `LOCAL_RERANK_URL=http://192.168.2.112:7997`.

Outage was about ten minutes. **Impact was zero**, because Graphiti's `fallback_reranker` caught the dead endpoint,
logged a WARNING, fell down to tier 1 (`gemini-2.5-flash-lite`), and served both affected calls. Restored and verified
end to end from homebox: `HTTP_STATUS=200 TIME=0.036s`. ContentFactory was never a consumer.

**Why the consumer check failed**, because the method error is reusable:
1. The dependency is a **container environment variable**, not source code. No source grep can see `docker inspect` env.
2. The consumer is on a **third machine**. I searched the Mac and lenovo; it was on neither.
3. `queue_absolute: 0` read as "abandoned" when it only means "not busy this second."

The service was naming its own caller 3,520 times in output I had already pulled:

```bash
docker logs infinity | grep -oE '"(GET|POST) [^ ]+ HTTP' | sort | uniq -c | sort -rn
#   3520 "POST /rerank HTTP
docker logs infinity | grep -oE '^INFO: +[0-9.]+:' | sort -u
# INFO:     192.168.2.110:
```

> **RULE: enumerate a service's callers from its own access log before stopping it, never from a source grep.**
> A source grep answers "who was written to call this," which is blind to env vars, containers, and other hosts.

Captured in the HNT inbox and in memory `lenovo-gpu-shared-with-graphiti-reranker`.

## 7. What to do next, in priority order

**1. Build a real spend stop before the first GPU VM.** R-3 and R-4 compound: launchable GPUs plus a
notification-only budget equals no enforced ceiling. A budget becomes a cap only when its Pub/Sub notification drives
a function that disables billing. **That function does not exist.** Today the only real controls are
`--max-run-duration` on instances and the teardown trap in `gate-0-plumbing.md`. This is now the highest-priority
build, and R-4 is why it comes *before* the sweep rather than after.

**2. Run Track A on lenovo.** Gate 0 (plumbing) then Gate 6 (restricted-egress / isolation). Both runbooks were
rewritten and neither has ever been executed. Budget ~9.3GB VRAM with the reranker up, or stop it deliberately and
restore it after:
```bash

ssh lenovo 'docker start infinity'   # ~8s to reload weights
```

**3. Author the fixtures.** `gcp-test-plan/fixtures/{agent-tasks,eval-scorers,embed-corpus}` are all `NOT WRITTEN`.
Preflight Rule 1 says no gate may be committed until the fixture validation gate passes. This is evaluation-methodology
design, not an upload; the original's "1-2 hours" estimate was for the wrong activity.

**4. Refresh the model list.** `10-PREFLIGHT.md` §1.3 is April 2026 vintage and says so. Verify current small,
coding, embedding and reasoning models before use rather than trusting those names. Same for the vLLM pin: `v0.6.5` is
a late-2024 release predating roughly two years of FlashAttention, batching and FP8 work, and
`vllm/vllm-openai:v0.6.5-cpu` **does not exist** (404).

**5. Fill the NOT SET thresholds in `POLICY-rent-first.md`.** DeepSeek's argument stands: a pre-commitment without a
named reopening condition is evidence insulation, not discipline. The numbers must come from measured spend and
utilization, so this waits on Track B.

**6. The five unrecovered findings.** Caught by the April twin review, never fixed, and **missed again by this
review**: human-in-the-loop operating protocol; continuous model evaluation; source-of-truth under concurrent edits;
**customer discovery as a gate before building**; client-codebase security across its lifecycle. Carried in
`twin-review-synthesis.md`. The fourth is uncomfortable in context: the corpus was rebuilt over one night without a
customer.

**7. Optional but cheap.** Alert on sustained tier-0 absence in Graphiti's reranker. The fallback converts loud
failures into quiet ones, which is right for uptime and wrong for detection; without an alert, running on the paid
fallback tier for weeks is invisible.
